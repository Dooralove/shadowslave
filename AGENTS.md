# Правила работы AI-агентов в проекте ShadowSlave

1. Не удаляй ресурсы, сцены, скрипты и ассеты без явного основания и подтверждения пользователя.
2. Не переписывай рабочие системы без необходимости. Небольшие точечные изменения предпочтительнее.
3. Проверяй изменения: открытие проекта, headless-импорт, парсинг GDScript, запуск тестов.
4. Не утверждай, что тест прошёл, без фактического запуска и вывода результата. Если проверка не выполнялась, так и пиши: NOT TESTED.
5. Балансные значения и характеристики храни в типизированных Godot Resources (`.tres`). JSON используй только для внешних данных, импортируемых таблиц и переносимых сценариев.
6. Не добавляй в Git-LFS текстовые форматы (`.gd`, `.tscn`, `.tres`, `.json`, конфигурации). Бинарные ассеты добавляй в `.gitattributes`.
7. Не записывай секреты, токены, `.env`, абсолютные пути в общие файлы конфигурации.
8. Не меняй глобальные настройки Git и не придумывай автора коммитов.
9. Не подключай удалённые репозитории и не отправляй код наружу без отдельного задания пользователя.
10. Решения, которые влияют на архитектуру или договорённости, фиксируй в `docs/DECISIONS.md`. Лицензии и источники ассетов — в `docs/ASSET_LICENSES.md`.
11. Godot MCP: при работе через MCP не меняй игровые ресурсы без необходимости. Для проверки используй read-only операции.

## Перед изменениями

Сначала изучи документацию проекта, затем меняй код или ассеты. Документация — источник истины по лору, локациям, последовательности событий и требованиям реализации.

- Общее: `README.md`, `docs/DECISIONS.md`, актуальный handoff (сейчас `docs/AI_HANDOFF_AFTER_S3_2.md`).
- По теме задачи: `docs/design/first_nightmare_*`, `docs/design/level_*`, `docs/story/*`, `docs/art/*`. Полный список — в `docs/`.
- Если документ противоречит памяти, догадке или старому комментарию в коде, прав документ. Расхождение зафиксируй в `docs/DECISIONS.md`.

- Экспериментальные файлы держи в `experiments/` (в `.gitignore`).

## Skills

Проектные skills лежат в `.opencode/skills/` и подхватываются автоматически:

- `graphics-production` — Blender-кит, PBR, свет, пост, оптимизация, проверки.
- `mcp-operations` — Godot/Blender MCP, статус, скриншоты, безопасные правки, troubleshooting.
- `forgotten-shore-art` — канон и арт-язык Лабиринта: 18 зон, прилив, гроза, палитра, запреты.
- `texture-toolchain` — Krita/Materialize/glTF-Transform, PBR-карты, decals, tiling, импорт.

Перед задачей загружай подходящий skill по точному ID. Skills — проектные, не глобальные; не дублируй их в `~/.config/opencode/skills` без необходимости.

## MCP-конфигурация

- `opencode.json` — `mcp.servers.godot` (`godot-mcp-server@0.6.1`) и `mcp.servers.blender` (`mcp-for-blender==2.2.6`).
- `.mcp.json` — те же два сервера для Claude/других MCP-клиентов.
- `project.godot` — autoload `MCPRuntime` и editor plugin `godot_mcp`.
- Версии MCP-серверов закреплены; после изменения конфигов нужен перезапуск OpenCode/клиента и повторная проверка статусов.
- Blender MCP addon auto-start включён; сервер слушает localhost:9876 по умолчанию. Godot MCP WebSocket — порт 6505.
- Runtime helper Godot может не подключаться из-за parse errors пользовательских скриптов; это не ошибка конфигурации. Для скриншотов без runtime используй `tools/audit/location_capture.gd`.
