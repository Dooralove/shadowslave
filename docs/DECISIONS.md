# Журнал решений ShadowSlave

## 2026-10-21 — Базовая среда разработки

- **Движок:** Godot 4.7.2 stable, Standard, GDScript. Установлен в `C:\Users\user\Tools\Godot\4.7.2`, путь добавлен в пользовательский PATH.
- **Расположение проекта:** `C:\Users\user\Desktop\shadowslave`. Диска D в системе нет, на диске C достаточно места, путь без пробелов.
- **MCP:** один сервер `godot` (пакет `godot-mcp-server`) с плагином `addons/godot_mcp/` из официального репозитория tomyud1/godot-mcp. Регистрация на уровне проекта.
- **Тесты:** GUT 9.7.1 в `addons/gut/`.
- **Git LFS:** только для бинарных форматов (FBX, GLB, GLTF, BLEND, WAV, OGG, PSD, KRA, XCF, TGA, EXR). Текстовые форматы остаются в обычном Git.
- **Данные баланса:** типизированные Godot Resources (`.tres`). JSON только для внешних данных.
- **Отложено:** Dialogic 2, Unreal Engine, Blender MCP, дополнительные MCP-серверы. Dialogic подключим после подтверждения работы проекта, управления персонажем и базовой сцены.

## 2026-10-21 — Milestone 1: управляемый персонаж и graybox-локация

- **Ввод:** только именованные действия Input Map (`move_forward/back/left/right`, `sprint`, `jump`, `release_mouse`, `capture_mouse`), привязки по физическим кодам клавиш — работают при любой раскладке. Скрипты не проверяют конкретные клавиши.
- **Персонаж:** `scenes/characters/sunny.tscn`, корень `CharacterBody3D` + `SunnyController`. Тело не вращается; поворачивается только узел `Visual`. Капсулу внутри `Visual` можно заменить моделью со скелетом и анимациями без изменения кода передвижения.
- **Камера:** `ThirdPersonCamera` (рыскание на узле, тангаж на `SpringArm3D`, предел −70°…+25°). Пружина с шаровой формой укорачивается при столкновении — защита от ухода под пол и в стены. Захват/освобождение мыши живёт в камере, т.к. связан только с обзором.
- **Локация:** `scenes/levels/test_level.tscn` из `CSGBox3D` с `use_collision` — graybox, без внешних ассетов. Сцена самодостаточна (свой экземпляр Санни) и запускается отдельно; `scenes/main/main.tscn` инстанцирует её как `Level`.
- **Godot MCP runtime:** автозагрузка `MCPRuntime` зарегистрирована (её регистрирует `_enable_plugin()` плагина; при установке плагин был включён правкой `project.godot`, поэтому хук не сработал). Нужна для `send_input`/`take_screenshot`/`query_runtime_node`. Перед релизной сборкой автозагрузку нужно убрать или исключить.
- **Кэш Godot MCP:** `addons/godot_mcp/cache/` исключён из Git (как в upstream). В `cache/undo/` лежит `.gdignore`: без него редактор импортирует снимки `project.godot`/`.tscn` и ловит дубликаты UID.

## 2026-10-21 — Milestone 2: первая боевая система

- **Компоненты** (`scripts/combat/`), одинаковые для Санни и противников:
  - `HealthComponent` — здоровье, урон, лечение, сигналы `health_changed`/`damaged`/`died`; `died` испускается ровно один раз, после смерти урон и лечение игнорируются.
  - `Hurtbox` (Area3D) — зона, по которой попадают; передаёт урон в свой `HealthComponent`.
  - `MeleeAttack` (Area3D) — удар: перезарядка, окно попадания, не больше одного попадания по каждому хёртбоксу за удар. Урон считается по пересечению областей, а не по мешу и не каждый кадр. `disable()` вызывается при смерти владельца.
  - `HitFlash` — визуальная реакция на урон по всем мешам под указанным узлом; от конкретной модели не зависит.
- **Баланс атак** — ресурс `AttackStats` (`.tres`): `resources/characters/sunny_attack.tres`, `resources/enemies/test_enemy_attack.tres`. Здоровье и параметры AI — экспортируемые свойства в сценах.
- **Слои физики** (именованы в `project.godot`): 1 `world`, 2 `player`, 3 `enemy`, 4 `player_hurtbox`, 5 `enemy_hurtbox`. Атака Санни видит только слой 5, атака противника — только слой 4, поэтому самоповреждения нет. SpringArm камеры по-прежнему видит только `world`.
- **Ввод:** `attack` — ЛКМ, `restart` — R. Щелчок, которым захватывается мышь, камера помечает обработанным — он не превращается в удар.

## 2026-10-21 — Milestone 2.1: направление атаки

- Санни бьёт туда, куда смотрит модель (`Visual`, ось −Z) в момент начала удара. Камера на направление удара не влияет и персонажа не разворачивает (раньше удар разворачивал модель к камере).
- `MeleeAttack` фиксирует свою глобальную ориентацию при начале удара и удерживает её до конца окна попадания: модель может продолжать поворачиваться по движению, а зона поражения, визуализация и урон остаются в исходном направлении. После удара атака снова следует за моделью.

## 2026-10-21 — Milestone 3: временная гуманоидная модель и анимации

- **Ассет:** KayKit Adventurers 1.0 `Rogue_Hooded.glb` (CC0) — Mixamo недоступен без входа в аккаунт Adobe. Модель и все анимации в одном файле, один скелет (41 кость) — ретаргетинг не нужен.
- **Импорт** — стандартный импортёр glTF Godot, настройки только в `.import`: зацикливание `Idle`, `Walking_A`, `Running_A`, `Jump_Idle`; не импортируются арбалеты и метательный предмет (остаются два ножа); материал заменён внешним `rogue_placeholder_dark.tres` (та же текстура, затемнённый тон под мрачный уровень).
- **Ориентация и масштаб:** модель смотрит вдоль своей +Z (проверено по костям стопы), а `Visual` — вдоль −Z, поэтому узел `Visual/Model` развёрнут на 180° вокруг Y. Высота модели ~2,25 м → масштаб 0,8 (≈1,8 м, как капсула коллизии). Коллизии, хёртбокс и камера не менялись.
- **Root motion не используется:** у клипов передвижения кость `root` неподвижна; `Death_A` смещает только `hips` внутри скелета. Перемещением по-прежнему управляет `CharacterBody3D`.
- **Анимации** — `SunnyAnimator` (`scripts/player/sunny_animator.gd`) над единственным `AnimationPlayer` модели, без `AnimationTree`: состояний мало, переходы читаются в коде и тестируются напрямую. Состояния: Idle/Walk/Run по фактической горизонтальной скорости (порог бега — середина между скоростями ходьбы и бега, скорость клипа подстраивается под скорость тела), Jump/Fall/Land по `is_on_floor` и вертикальной скорости (короткий отрыв < 0,12 с падения не включает), Attack по сигналу `attack_started`, Hit по `damaged`, Death по `died`.
- **Аниматор только визуальный:** урон наносит `MeleeAttack`, здоровье — `HealthComponent`. Повторный вход в Attack не открывает окно попадания и не наносит урон. Hit не прерывает удар (чтобы анимация совпадала с окном попадания). Death финальна: аниматор перестаёт обновляться и игнорирует сигналы. Наклон `Visual` при смерти из контроллера удалён — его заменяет клип.
- **Синхронизация удара:** окно попадания открывается сразу по нажатию на 0,15 с, а пик замаха `1H_Melee_Attack_Slice_Horizontal` — на 0,267 с клипа. Игровые тайминги не менялись: клип стартует с 0,192 с, чтобы пик пришёлся на середину окна. Цена — пропущен замах (удар без подготовки). Если нужна подготовка, безопасный вариант — добавить в `MeleeAttack` задержку открытия окна (это изменит тайминг боя, требует решения).
- **Противник** пока остаётся капсулой: отдельная анимационная система для него не нужна на этом этапе.

## 2026-10-21 — Milestone 4: фазы атаки и анимированный противник

- **Фазы атаки** в `MeleeAttack`: READY → WINDUP → ACTIVE → RECOVERY. Хитбокс засчитывает попадания только в ACTIVE, по-прежнему не больше одного попадания по цели за атаку. Направление фиксируется при старте (уже на подготовке). `disable()` при смерти обрывает атаку в любой фазе. Восстановление — остаток `cooldown` после окна, поэтому длина цикла атаки не изменилась. Сигналы: `attack_started`, `hit_window_opened`, `hit_window_closed`, `attack_finished`, `hit_landed`.
- **Тайминги по реальным кадрам.** Момент контакта измерен покадрово (1/60 с) по позе скелета: скорость кости `handslot.r` перед корпусом. Санни, `1H_Melee_Attack_Slice_Horizontal`: замах 0–0,20 с, контакт 0,25 с, доводка до 0,35 с → `windup_time = 0.2` (новый параметр `AttackStats`), `active_time = 0.15` и `cooldown = 0.5` без изменений. Клип играет с начала, скорость клипа ≈ 0,91 так, чтобы контакт пришёлся на середину окна (0,275 с от нажатия). Если поменять подготовку или окно в данных, анимация пересчитается сама.
- **Модель не поворачивается во время атаки** (0,5 с): видимый удар всегда совпадает с зафиксированной зоной поражения. Передвижение во время атаки не меняется.
- **Противник:** KayKit Barbarian (CC0, тот же скелет и набор клипов), двуручный топор, затемнённый красно-коричневый материал. Отдельная модель вместо перекрашенного Rogue — чтобы силуэты игрока и противника различались. Игровые узлы, коллизии, здоровье и автомат не менялись.
- **`EnemyAnimator`** следует за `TestEnemy.state_changed`: Idle → `2H_Melee_Idle`, Chase → `Walking_A` (скорость по скорости погони), Telegraph → Attack → Recovery — один непрерывный `2H_Melee_Attack_Chop`: замах занимает подготовку (0–0,6 с), контакт 0,717 с попадает в окно 0,6–0,8 с (скорость клипа ≈ 1,02), доводка служит восстановлением, затем стойка. Hit → `Hit_A` только вне подготовки и удара; Death → `Death_B`, финально. Отдельного клипа «восстановления» в паке нет — используется доводка удара.
- **Обратная связь:** зона удара — только отладка (`MeleeAttack.show_hit_zone`, по умолчанию выключено, на физику не влияет). Вспышка урона мягче (альфа 0,3, 0,1 с) и исправлена: быстрые повторные попадания больше не гасят её раньше времени. Новый `HitSpark` — короткая вспышка в точке контакта, только по факту попадания.
- **Наклон `Visual` при смерти противника** удалён — его заменяет клип смерти.
- **Противник** `TestEnemy`: автомат Idle → Chase → Telegraph → Attack → Recovery, из любого состояния → Dead. Логика состояний (`update_ai`) отделена от перемещения. При входе в Telegraph противник разворачивается к цели, затем направление удара фиксируется — от удара можно уйти в сторону. Мёртвое тело остаётся, но получает `collision_layer = 0` и не загораживает проход.
- **Боевое испытание:** `scenes/levels/combat_arena.tscn` инстанцирует существующую `test_level.tscn` и добавляет противника и HUD. Главная сцена не менялась.

## 2026-10-21 — S1: graybox-срез «Nightmare Begins» (B01–B16)

- **Запуск:** `scenes/slice/prologue.tscn` (корень — `SliceDirector`). `main.tscn`, арена и тестовая локация не менялись.
- **Сценарий отделён от визуала.** Режиссёр (`scripts/slice/slice_director.gd`) знает только биты и события: взаимодействие (`interact:<id>`), триггер (`trigger:<id>`), конец диалога или постановки, `open_status`. Событие засчитывается, только если сценарий ждёт именно его, поэтому биты не перескакивают. Локации — наследники `SliceLocation` с единым интерфейсом: `Spawns/*`, `Shots/*` (ракурс смотрит на дочерний `LookAt`), `Interactable`, `TriggerZone`, `play_cutscene(id, fast)`, `march_velocity()`. Постановки сейчас на твинах; заменить их на `AnimationPlayer` или реалистичные модели можно, не трогая режиссёр.
- **Персонаж в постановках:** `CinematicActor` + `ActionClipMap` (`resources/slice/sunny_kaykit_clips.tres`) переводят логические действия («сесть», «встать», «бросить») в имена клипов. Новая модель — новая карта клипов. На время постановки актёр включает у `SunnyAnimator` режим `cinematic`, чтобы два источника не делили кости.
- **Сцена Санни для пролога** — `sunny_waking.tscn`, наследник `sunny.tscn`: без боя, бега и прыжка, с `Interactor` и `CinematicActor`; ножи временной модели скрыты; стойка без оружия (`Unarmed_Idle`). Санни арены прежний (проверено тестами и прогоном).
- **Изменения общих скриптов только аддитивные**, значения по умолчанию сохраняют старое поведение:
  - `SunnyController`: `allow_sprint`, `allow_jump`, `combat_enabled` (экспорт); `input_enabled` и `forced_velocity` (шаг в цепи без ввода);
  - `ThirdPersonCamera`: `look_enabled`;
  - `SunnyAnimator`: режим `cinematic`. Тело с выключенной физикой (диалог, постановка) считается стоящим: раньше `is_on_floor()` у такого тела не обновлялся, и аниматор включал клип падения.
- **Режимы управления:** FREE, LOOK (сидя, пристёгнутым, в диалоге — только обзор и взаимодействие), LOCKED (постановки), CHAINED (шаг в темпе цепи с обзором). Сидя и в постановках физика тела выключена — Санни не падает со скамейки и стула.
- **Ввод:** `interact` (E), `advance_dialogue` (E, Space, Enter), `open_status` (Tab). Двойное срабатывание E исключено: проигрыватель диалога и экран рун игнорируют нажатие в кадре, в котором открылись, а во время реплик взаимодействия выключены.
- **Данные — в `.tres`:** диалоги (`resources/dialogue/prologue/*.tres`, `DialogueSequence` из `DialogueLine`; длительность > 0 — реплика идёт сама, 0 — ждёт «далее»), лист статуса (`resources/spell/sunny_status.tres`). Реплики — русский пересказ первоисточника, не цитаты. Значения рун — канонические английские (Sunless, Aspirant, Dormant, [Fated], [Mark of Divinity], [Child of Shadows], [Temple Slave]).
- **Временный контент:** шесть локаций из CSG (сквер и улица, лобби, изолятор, тьма, видение горы, дорога каравана); NPC — собственный манекен из примитивов (`scenes/slice/props/mannequin.tscn`). Постановки двигают узел манекена, а не меши, поэтому замена на модель не меняет сценарий. Новых внешних ассетов нет.
- **Караван:** темп задаёт локация (`march_velocity()`), цепь держится вровень с Санни вдоль дороги. Физика тела на склоне чуть отстаёт от расчётного темпа, и без привязки звенья расходились бы.
- **Отладочный замер:** `PerfProbe` (выключен по умолчанию) копит время кадров по битам — среднее FPS, 1 % худших кадров, максимальный кадр.
- **Предупреждение анализатора** `REDUNDANT_AWAIT` в `SliceDirector._cutscene` подавлено точечно. Базовый `play_cutscene` не корутина, переопределения в локациях — корутины. То, что `await` ждёт конца постановки, проверено замером длительностей битов и тестом `test_cutscene_blocks_script_in_real_time`.
- **Известные упрощения graybox:** глоток кофе без анимации руки (стаканчик стоит на скамейке); NPC без анимаций; подъём со скамейки доводится сдвигом; сонливость — затемнение краёв. Всё это задачи S2–S7.
