# Спецификация восстановления Первого Кошмара

Статус: **C4–C8 реализованы, C9 — документация; спецификация обновлена по фактическому маршруту**  
Дата: 2026-10-24  
Опирается на: `docs/story/first_nightmare_canonical_timeline.md`, `docs/design/first_nightmare_scene_matrix.md`, `docs/design/first_nightmare_route_verification.md`.  
Назначение: превратить 20 канонических блоков в упорядоченные игровые сегменты с входами, выходами, состоянием, триггерами, обязательными текстами, минимальной геометрией, политикой катсцен и критериями приёмки.

**Важно:** это спецификация и отчёт о состоянии, а не разрешение менять сцены. Фактический маршрут и флаги сверяются с `first_nightmare_scene_matrix.md`; пометки `[NEW]` ниже сохранены как история проектирования, но соответствующие сцены уже существуют.

## 0. Принципы восстановления

1. **Не переписывать пролог.** B01–B16 уже связаны с кампанией. Их задача — сохранить вход, а не заменить его текстовым пересказом.
2. **Один канонический Санни.** Все сюжетные сцены используют одну утверждённую модель. Пока решение не принято, рабочая модель — `assets/characters/sunny_realistic_poc/sunny_waking_poc.tscn`, но это **не** означает официального принятия.
3. **Никаких воскрешений.** Смерти фиксируются флагами; персонаж не появляется после смерти, даже если модель осталась в сцене.
4. **Цепь снимается после ключа.** До освобождения она ограничивает; после — остаётся инструментом/реквизитом, но не поводком Санни.
5. **Испытание ≠ оценка.** Смерть Тирана и три сообщения завершения — глава 14. Оценка, True Name, Аспект и First Seal — глава 15. Пробуждение — глава 16.
6. **Финальное событие — только после оценки.** Карточка/переход не могут срабатывать от подношения, крови или смерти Тирана.
7. **Не делать один длинный фильм.** Каждый сегмент имеет действие игрока; катсцена без ввода — не длиннее 45–60 секунд, длинная экспозиция делится на диалог/действия.
8. **Не строить сложный бой ради сюжета.** Тиран в караване — угроза и физика; в храме его убивают тени. Полоса здоровья и свободный бой не нужны.
9. **Сначала вертикальный срез.** Сначала S00–S03 (пролог, марш, лагерь, нападение/личинка), визуальная проверка, затем остальное. Не детализировать всё до согласования направления.
10. **Пропуск катсцен.** После первого просмотра — можно, если смысл остаётся в журнале/субтитрах. Ключевые интерактивные действия (звонок, ключ, алтарь) не пропускаются. Первый показ ключевых смертей и оценки не пропускается.

## 1. Целевая архитектура

### 1.1. Маршрут

```text
scenes/campaign/campaign_entry.tscn
  └─ scenes/slice/prologue.tscn                         [ГОТОВО]  S00
       ↓ prologue_completed
scenes/campaign/first_nightmare_pass.tscn               [ГОТОВО]  S01
  └─ scenes/slice/locations/caravan_road.tscn
       ↓ CampArrival / camp_reached
scenes/campaign/caravan_site_arrival.tscn               [ГОТОВО]  S02–S06
  └─ scenes/locations/caravan_site/caravan_site.tscn     [ГОТОВО]
       ↓ dawn_departure
scenes/campaign/pilgrim_path_arrival.tscn               [ГОТОВО]  S07–S12
  └─ scenes/locations/pilgrim_path/pilgrim_path.tscn     [ГОТОВО]
       ↓ temple_reached
scenes/campaign/sanctuary_arrival.tscn                  [ГОТОВО]  S13
  └─ scenes/locations/shadow_sanctuary/shadow_sanctuary.tscn
       ↓ trial_completed / tyrant_death_confirmed
scenes/campaign/appraisal_arrival.tscn                  [ГОТОВО]  S14
       ↓ appraisal_completed
scenes/campaign/finale_arrival.tscn                     [ГОТОВО]  S15
       ↓ first_nightmare_completed
финальная карточка / R → campaign_entry
```

Оценка и финал — UI-сцены внутри `appraisal_arrival.tscn` и `finale_arrival.tscn`; отдельных `appraisal_space.tscn` и `finale.tscn` нет.

`scenes/campaign/caravan_ambush.tscn` и `scenes/levels/ambush_site_demo.tscn` **не** входят в канонический маршрут. Их можно оставить как sandbox для проверки укрытия/побега; не удалять без отдельного согласования.

### 1.3. `NightmareRunState` (autoload)

Реализовано: `scripts/campaign/nightmare_run_state.gd` зарегистрирован как autoload `NightmareRunState` в `project.godot`.

Минимальный контракт:

```gdscript
# Контракт autoload; фактический API совпадает по смыслу.
signal flag_changed(name: StringName, value: bool)

func reset() -> void
func set_flag(name: StringName, value := true) -> void
func has_flag(name: StringName) -> bool
func require(flags: Array[StringName]) -> bool
func set_item(id: StringName, count := 1) -> void
func has_item(id: StringName) -> bool
func snapshot() -> Dictionary
```

Правила:

- `reset()` вызывается при старте кампании и по `R`.
- Флаги не хранятся в сценах-одиночках и не теряются при `change_scene_to_file`.
- Инвентарь — только сюжетные предметы: `silver_bell`, `cloak`, `boots`, `flasks`, `sword`, `key`, `puppeteer_shroud`, `shadow_blessing`.
- `key` расходуется при освобождении; `sword` удаляется в S07; `silver_bell` остаётся Памятью после использования.
- Для отладки — `debug_direct_scene`; он не должен позволять финальную карточку без оценки.

### 1.4. Единая модель

Все сюжетные сцены ссылаются на одну сцену Санни. Для C4–C8 используется:

```text
assets/characters/sunny_realistic_poc/sunny_waking_poc.tscn   # рабочая модель кампании
scenes/characters/sunny_waking.tscn                            # базовая/fallback, не смешивать
```

POC означает «рабочая модель», а не официальное художественное утверждение. Не смешивать POC и KayKit в одной кампании. Решение зафиксировано в `docs/DECISIONS.md`.

### 1.5. Переходы и предусловия

| Переход | Условие | Выходное состояние |
|---|---|---|
| `campaign_entry` → `first_nightmare_pass` | `slice_finished`; `prologue_completed` | `march_intro_seen` ещё не установлен |
| `first_nightmare_pass` → `caravan_site_arrival` | `CampArrival`; `march_intro_seen` | `camp_reached = true`; цепь активна |
| `caravan_site` → `pilgrim_path_arrival` | `dawn_departure`; четверо живы | `road_gap_seen` и `sword_discarded` ещё не установлены |
| `pilgrim_path` → `sanctuary_arrival` | `temple_reached`; `wound_taken`; `hero_dead` | `trial_completed` ещё не установлен |
| `sanctuary_arrival` → `appraisal_arrival` | `trial_completed`; `tyrant_death_confirmed` | `appraisal_completed` ещё не установлен |
| `appraisal_arrival` → `finale_arrival` | `appraisal_completed`; `temple_reached`; `trial_completed` | `first_nightmare_completed` ещё не установлен |
| `finale_arrival` → card | `temple_reached && trial_completed && appraisal_completed` | `first_nightmare_completed = true` |
| card → `campaign_entry` | `restart` | `NightmareRunState.reset()` |

**Жёстко:** переход в `finale_arrival` невозможен без `temple_reached`, `trial_completed` и `appraisal_completed`. Один `appraisal_completed` без `temple_reached` — ошибка состояния, а не повод показать карточку. В коде канонический флаг входа в храм — `temple_reached`; старое `temple_entered` в тексте считается устаревшим синонимом.

## 2. Обозначения состояния

### 2.1. Режимы игрока

| Режим | Что можно | Где используется |
|---|---|---|
| `FREE` | Полное движение в границах локации | Лагерь после цепи, тропа, храм |
| `LOOK` | Стоять/сидеть, осматриваться, взаимодействовать; без бега | Диалоги, камера, осмотр |
| `CHAINED` | Автоматический/полуавтоматический марш в коридоре цепи | S01, начало S02 |
| `CAMP_CHAINED` | Малый радиус у костра, цепь прикреплена к повозке | S02 |
| `LOCKED` | Ввод заблокирован, кроме продвижения диалога | Катсцены, смерть, оценка |

### 2.2. Инвентарь и состояния

| ID | Когда | Правило |
|---|---|---|
| `key` | S03 | Расходуется при освобождении; после — нет |
| `silver_bell` | S06 | Память; используется в S11; остаётся в списке после звонка |
| `cloak`, `boots` | S06 | Тёплые вещи; не броня |
| `flasks` | S05–S06 | Часть отравлена; не лечат |
| `sword` | S06 | Брошен в S07; после — нет |
| `puppeteer_shroud` | S14 | Память Awakened; не влияет на бой в этой сцене |
| `shadow_blessing` | S13 | Связан с Aspect Shadow Slave; выдаётся после смерти Тирана |

Фактически `shadow_blessing` выдаётся в S13, `puppeteer_shroud` — в S14. `mark_of_divinity` — не предмет, а флаг-атрибут: выставляется в B16 и отображается в статусе; страж храма B3 ещё не реализован.

### 2.3. Глобальные проверки

```text
assert shifty_dead after S08
assert scholar_abandoned after S09
assert hero_dead after S11

```
