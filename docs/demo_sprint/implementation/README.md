# Implementation — планы и журнал интеграции

## Назначение

Фиксировать, кто что меняет, в каком порядке и с каким результатом. Это защита от «десяти несовместимых наборов изменений».

## Файлы

| Файл | Назначение |
|---|---|
| `ACTIVE_CLAIMS.md` | кто держит какой файл, зачем и до какого времени |
| `INTEGRATION_LOG.md` | хронология сборки, проверки, откаты |
| `P0_BOARD.md` | статус P0-задач и владельцев |

## Правила

1. Перед правкой — записать claim.
2. После правки — целевой тест и запись результата.
3. Общие файлы — только после подтверждения TD.
4. Не коммитить; коммит делает TD.
5. Если правка не влезла в окно — освободить claim и записать статус.
6. Все результаты — с командами и exit code; иначе **NOT TESTED**.
